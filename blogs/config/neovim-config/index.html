This is a portable snapshot of my Neovim config. It is here so I can track changes over time and bootstrap a new machine from the same files.

Current shape: LazyVim baseline, Catppuccin with automatic light/dark switching, Markdown/Python/TOML extras, Black and Prettier formatting, auto-save, and a quick Codex terminal pane.

Install on a new machine
#

Install directly from GitHub:

1curl -fsSL https://raw.githubusercontent.com/tihaya-anon/tihaya-anon.github.io/main/scripts/install-neovim-config.sh | sh

The script downloads the repo archive, copies dotfiles/nvim into ${XDG_CONFIG_HOME:-$HOME/.config}/nvim, and moves any existing config to a timestamped backup path first.

Check the plan without changing files:

1curl -fsSL https://raw.githubusercontent.com/tihaya-anon/tihaya-anon.github.io/main/scripts/install-neovim-config.sh | sh -s -- --dry-run

If the repo is already cloned locally, run the same installer from the checkout:

1sh scripts/install-neovim-config.sh

The files load in this order:

  1. init.lua loads lua/config/lazy.lua.
  2. LazyVim loads lua/config/options.lua before lazy.nvim startup. That file reads the system theme and configures automatic theme refresh.
  3. lua/config/lazy.lua bootstraps lazy.nvim, imports LazyVim, and then imports local plugin specs from lua/plugins.
  4. lazyvim.json enables the LazyVim extras for Black, Prettier, Markdown, Python, and TOML.
  5. Plugin specs under lua/plugins configure Catppuccin, Mason, and auto-save.
  6. LazyVim loads lua/config/keymaps.lua and lua/config/autocmds.lua on VeryLazy, adding the Codex shortcut and Markdown wrapping behavior.

init.lua
#

The entrypoint does one thing: hand control to the LazyVim bootstrap file.

1-- bootstrap lazy.nvim, LazyVim and your plugins
2require("config.lazy")

lua/config/lazy.lua
#

This file installs lazy.nvim into Neovim’s data directory when it is missing, then configures LazyVim. Custom plugin specs are loaded from lua/plugins.

 1local lazypath = vim.fn.stdpath("data") .. "/lazy/lazy.nvim"
 2if not (vim.uv or vim.loop).fs_stat(lazypath) then
 3  local lazyrepo = "https://github.com/folke/lazy.nvim.git"
 4  local out = vim.fn.system({ "git", "clone", "--filter=blob:none", "--branch=stable", lazyrepo, lazypath })
 5  if vim.v.shell_error ~= 0 then
 6    vim.api.nvim_echo({
 7      { "Failed to clone lazy.nvim:\n", "ErrorMsg" },
 8      { out, "WarningMsg" },
 9      { "\nPress any key to exit..." },
10    }, true, {})
11    vim.fn.getchar()
12    os.exit(1)
13  end
14end
15vim.opt.rtp:prepend(lazypath)
16
17require("lazy").setup({
18  spec = {
19    -- add LazyVim and import its plugins
20    { "LazyVim/LazyVim", import = "lazyvim.plugins" },
21    -- import/override with your plugins
22    { import = "plugins" },
23  },
24  defaults = {
25    -- By default, only LazyVim plugins will be lazy-loaded. Your custom plugins will load during startup.
26    -- If you know what you're doing, you can set this to `true` to have all your custom plugins lazy-loaded by default.
27    lazy = false,
28    -- It's recommended to leave version=false for now, since a lot the plugin that support versioning,
29    -- have outdated releases, which may break your Neovim install.
30    version = false, -- always use the latest git commit
31    -- version = "*", -- try installing the latest stable version for plugins that support semver
32  },
33  install = { colorscheme = { "tokyonight", "habamax" } },
34  checker = {
35    enabled = true, -- check for plugin updates periodically
36    notify = false, -- notify on update
37  }, -- automatically check for plugin updates
38  performance = {
39    rtp = {
40      -- disable some rtp plugins
41      disabled_plugins = {
42        "gzip",
43        -- "matchit",
44        -- "matchparen",
45        -- "netrwPlugin",
46        "tarPlugin",
47        "tohtml",
48        "tutor",
49        "zipPlugin",
50      },
51    },
52  },
53})

The important defaults here are lazy = false for personal plugin specs and version = false for plugin sources. This favors current upstream commits over semver tags, while lazy-lock.json records the exact commits that were installed at the time.

Theme switching
#

The theme now follows the operating system instead of staying on a fixed Catppuccin flavor.

lua/config/options.lua loads the helper before lazy.nvim startup:

1-- Options are automatically loaded before lazy.nvim startup
2-- Default options that are always set: https://github.com/LazyVim/LazyVim/blob/main/lua/lazyvim/config/options.lua
3-- Add any additional options here
4local system_theme = require("config.system_theme")
5
6vim.o.background = system_theme.get()
7system_theme.setup()

lua/config/system_theme.lua detects the current platform theme:

  1local M = {}
  2
  3local function system(command)
  4  local result = vim.system(command, { text = true }):wait()
  5
  6  if result.code ~= 0 then
  7    return nil
  8  end
  9
 10  return result.stdout or ""
 11end
 12
 13local function is_wsl()
 14  local files = { "/proc/sys/kernel/osrelease", "/proc/version" }
 15
 16  for _, file in ipairs(files) do
 17    local ok, lines = pcall(vim.fn.readfile, file)
 18    local text = ok and table.concat(lines, "\n"):lower() or ""
 19
 20    if text:find("microsoft", 1, true) or text:find("wsl", 1, true) then
 21      return true
 22    end
 23  end
 24
 25  return false
 26end
 27
 28local function macos_theme()
 29  local result = vim
 30    .system({
 31      "defaults",
 32      "read",
 33      "-g",
 34      "AppleInterfaceStyle",
 35    }, { text = true })
 36    :wait()
 37
 38  return result.code == 0 and "dark" or "light"
 39end
 40
 41local function windows_theme(command)
 42  local stdout = system({
 43    command,
 44    "query",
 45    [[HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize]],
 46    "/v",
 47    "AppsUseLightTheme",
 48  })
 49
 50  if not stdout then
 51    return nil
 52  end
 53
 54  if stdout:find("0x0", 1, true) then
 55    return "dark"
 56  end
 57
 58  if stdout:find("0x1", 1, true) then
 59    return "light"
 60  end
 61
 62  return nil
 63end
 64
 65local function linux_theme()
 66  local color_scheme = system({
 67    "gsettings",
 68    "get",
 69    "org.gnome.desktop.interface",
 70    "color-scheme",
 71  })
 72
 73  if color_scheme and color_scheme:find("dark", 1, true) then
 74    return "dark"
 75  end
 76
 77  local gtk_theme = system({
 78    "gsettings",
 79    "get",
 80    "org.gnome.desktop.interface",
 81    "gtk-theme",
 82  })
 83
 84  if gtk_theme and gtk_theme:lower():find("dark", 1, true) then
 85    return "dark"
 86  end
 87
 88  if color_scheme or gtk_theme then
 89    return "light"
 90  end
 91
 92  return nil
 93end
 94
 95local function reload_colorscheme()
 96  local colorscheme = vim.g.colors_name
 97
 98  if colorscheme and colorscheme ~= "" then
 99    vim.schedule(function()
100      pcall(vim.cmd.colorscheme, colorscheme)
101    end)
102  end
103end
104
105function M.get()
106  local os = vim.uv.os_uname().sysname
107
108  if os == "Darwin" then
109    return macos_theme()
110  end
111
112  if os == "Linux" and is_wsl() then
113    return windows_theme("reg.exe") or linux_theme() or "dark"
114  end
115
116  if os == "Linux" then
117    return linux_theme() or "dark"
118  end
119
120  if os == "Windows_NT" then
121    return windows_theme("reg") or "dark"
122  end
123
124  return "dark"
125end
126
127function M.update()
128  local background = M.get()
129
130  if vim.o.background == background then
131    return
132  end
133
134  vim.o.background = background
135  reload_colorscheme()
136end
137
138function M.setup()
139  local group = vim.api.nvim_create_augroup("SystemTheme", { clear = true })
140
141  vim.api.nvim_create_autocmd({ "FocusGained", "VimResume" }, {
142    group = group,
143    callback = M.update,
144  })
145
146  vim.api.nvim_create_user_command("SystemThemeUpdate", M.update, {})
147end
148
149return M

The helper checks macOS with defaults, Windows with the registry, WSL with reg.exe, and GNOME Linux with gsettings. If detection fails, it falls back to dark mode. The SystemThemeUpdate command can be run manually, and Neovim also refreshes the theme when the editor regains focus or resumes.

lua/config/autocmds.lua
#

LazyVim’s default text autocmd group enables wrap and spell for Markdown and text-like filetypes. I still want wrapped prose, but I do not want English spell checking to light up Markdown documents, especially when writing mixed technical notes.

The override removes the LazyVim group, restores the original behavior for plain text, Typst, and git commits, then gives Markdown its own rule with better soft wrapping.

 1-- Autocmds are automatically loaded on the VeryLazy event
 2-- Default autocmds that are always set: https://github.com/LazyVim/LazyVim/blob/main/lua/lazyvim/config/autocmds.lua
 3--
 4-- Add any additional autocmds here
 5-- with `vim.api.nvim_create_autocmd`
 6--
 7-- Or remove existing autocmds by their group name (which is prefixed with `lazyvim_` for the defaults)
 8-- e.g. vim.api.nvim_del_augroup_by_name("lazyvim_wrap_spell")
 9pcall(vim.api.nvim_del_augroup_by_name, "lazyvim_wrap_spell")
10
11local group = vim.api.nvim_create_augroup("user_wrap_spell", { clear = true })
12
13vim.api.nvim_create_autocmd("FileType", {
14  group = group,
15  pattern = { "text", "plaintex", "typst", "gitcommit" },
16  callback = function()
17    vim.opt_local.wrap = true
18    vim.opt_local.spell = true
19  end,
20})
21
22vim.api.nvim_create_autocmd("FileType", {
23  group = group,
24  pattern = "markdown",
25  callback = function()
26    vim.opt_local.wrap = true
27    vim.opt_local.linebreak = true
28    vim.opt_local.breakindent = true
29    vim.opt_local.spell = false
30  end,
31})
32
33vim.api.nvim_create_autocmd("FocusGained", {
34  callback = function()
35    require("config.system_theme").update()
36  end,
37})

The extra FocusGained hook is redundant with system_theme.setup(), but it is harmless because the update function exits early when the background already matches the system.

lua/config/keymaps.lua
#

The only custom keymap opens Codex in a right-side Snacks terminal from the current LazyVim project root.

 1-- Keymaps are automatically loaded on the VeryLazy event
 2-- Default keymaps that are always set: https://github.com/LazyVim/LazyVim/blob/main/lua/lazyvim/config/keymaps.lua
 3-- Add any additional keymaps here
 4vim.keymap.set("n", "<leader>ac", function()
 5  Snacks.terminal("codex", {
 6    cwd = LazyVim.root(),
 7    win = {
 8      position = "right",
 9      width = 0.4,
10    },
11  })
12end, { desc = "Codex" })

Plugin specs
#

lua/plugins/autosave.lua adds automatic writes after leaving insert mode or when text changes:

1return {
2  {
3    "okuuva/auto-save.nvim",
4    event = { "InsertLeave", "TextChanged" },
5    opts = {},
6  },
7}

lua/plugins/mason.lua keeps Mason’s bin directory after the system path instead of before it:

1return {
2  {
3    "mason-org/mason.nvim",
4    opts = {
5      PATH = "append",
6    },
7  },
8}

lua/plugins/example.lua is still the LazyVim template. It returns an empty spec and does not load anything.

The .gitignore keeps local scratch files, generated tags, logs, debug output, and LazyVim’s local data directory out of the config repository.

Lock file notes
#

lazy-lock.json is the reproducibility layer. The current snapshot pins the LazyVim core, lazy.nvim, Catppuccin, completion, LSP, Treesitter, Markdown, formatting, diagnostics, UI, auto-save, Python environment selection, and Git helper plugins to specific commits.

When moving this config to another machine, use scripts/install-neovim-config.sh. It copies the Lua files, lazyvim.json, lazy-lock.json, and the small tooling files together. Run :Lazy sync after the files are in place if plugins need to be installed or refreshed.
